# dmxo deployment

`dmxo/production` is the deployment branch; `upstream` is `milind-soni/OpenMausBot`.
The fork retains the upstream license, attribution and main branch. Custom source
integrations live in `server/dmxo` and their call sites. Credentials, bot data,
workspace files and server-specific configuration are kept outside Git.

The server uses Azure GPT-6 Responses transport, bounded immediate tool recovery,
patch/diff attachments, a guarded desktop startup wait, Git/AWS workspace identity
provisioning and development tools in each native Cua desktop. Dedicated AWS
identities are matched to their exact workspace before credentials are copied;
other desktops keep their shared configured role. The code grants no AWS or DB
permissions by itself. Codex bot subprocesses disable the native GitHub plugin so
GitHub API calls use the workspace Connected Apps/Composio identity. This does not
uninstall the personal plugin or disable other Codex apps.

## Build

```sh
SOURCE_REVISION=$(git rev-parse HEAD)
docker build -f deploy/dmxo/Dockerfile --build-arg SOURCE_REVISION="$SOURCE_REVISION" -t openmausbot-dmxo:"$SOURCE_REVISION" .
```

`Dockerfile.artifacts` produces the same runtime from a context containing the
`dist` and `dist-server` directories built from this source, plus the desktop
Dockerfile generated by `node --experimental-strip-types scripts/dmxo-desktop.ts desktop.Dockerfile`. Both Dockerfiles pin
the upstream 0.1.141 runtime by digest. The upstream runtime supplies Chrome and
native dependencies; the complete server and browser bundles come from the fork.

## Update

1. Fetch upstream tags and merge the selected stable tag into a candidate branch
   based on `dmxo/production`. Resolve source conflicts and retain custom call sites.
2. Update the upstream runtime digest in both Dockerfiles to the same release.
3. Install the frozen lockfile. Run TypeScript checks, relevant Vitest suites,
   `node --test server/dmxo/*.test.mjs`, lint, locale checks and production builds.
   Follow `docs/verification/README.md` with isolated data and a fake engine.
4. Build and boot a canary container without production volumes or credentials.
   Check installed/latest versions, the UI and native desktop settings. If the
   Cua image layer changed, build the new desktop image and qualify a disposable
   desktop before restarting the app.
5. Keep the prior image and Compose file. Wait until bots are idle, back up the
   application metadata/configuration, then replace only the app container and
   verify read-only health/version endpoints. Preserve native workspace binds and
   identity stores. Roll back the image/Compose file if activation fails; a
   release with incompatible data migrations also needs its matching data backup.
6. Push the verified source to `dmxo/production` and record its full commit and
   image ID. Keep `main` available as the untouched upstream branch.

The menu checks for releases hourly. It does not change containers or execute
`git pull`. Source updates and deployment are deliberate operations.
